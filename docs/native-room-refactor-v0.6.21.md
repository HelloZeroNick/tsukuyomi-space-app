# Room 交互与聊天渲染重构

0.6.21+28 / v0.6.21-beta.1。基线源码为 `1757f5ebaa2f9cf0fb40007f3384ad090b09dd35`，继续使用原后端、账号和模型配置。

## 更新范围

RoomPage只协调布局、导航和房间操作；RoomComposer独立持有输入控制器、焦点、组合文字和快捷键。RoomChatView独立持有滚动位置、可见记录索引、回复／图片缓存和新消息提示。导航、舞台、工作区、聊天壳和同步状态通过RoomSelector只监听其实际显示的字段。流式文本改为缓冲增量累计，只在32ms界面读取时取得共享快照，避免每个碎片复制完整回复。输入法逐帧高度变化由布局组件接收，稳定导航与聊天子树复用，避免遍历整页。

聊天列表从「一轮对话一个大Column」改为图片、问题、回复气泡、操作与待同步状态的惰性行。历史只先分配记录引用，滚动到某轮时才解析该轮回复；已经显示的行使用稳定ID和有限缓存。近期回复增量解析，向上历史保留固定中心，查看旧消息时追加回复不跳动。跟随与新消息定位检查有限滚动范围。历史弹窗使用相同惰性行，不再一次创建全部记录。

长Markdown先统一解析和清理，再按顶层HTML块分段渲染，引用链接在完整文档中解析。代码块、表格和列表保持完整；短内容保持原排版。跨段页内锚点／脚注继续使用完整文档以保留跳转语义，此类超长内容和单个巨大表格／代码块仍是原子渲染单元。普通文字与流式分句只创建屏幕附近的行。

RoomInteraction统一报告拖动与惯性滚动、120ms输入突发以及180ms键盘高度过渡。舞台暂时停止模型时钟，保留已完成的2048纹理绘制快照；最多让已经开始的一帧完成。交互结束重置时间基准再继续，动作队列不丢失，不累计暂停时间。不会因为聊天掉帧而永久降低模型清晰度。全屏、暂停静态刷新、后台及最小化沿用原有资源与生命周期保护。

模型绘制增加独立的异步准备／完成／丢弃／耗时记录，因为异步离屏工作不一定出现在当前可见帧的Raster统计中；这些耗时不是GPU占用百分比。试验过共享遮罩显示列表缓存，重复测量后CPU开销变高，未采用该方案。

## 原生 macOS 三轮对比

同一Apple M5／16GB／macOS27.0.1、1280×820 / DPR2，2048纹理与auto600k预算，2,000条记录、200条图片消息、240片段流式回复和10次持续拖动。基线与候选使用SHA256相同的测试入口，前台、空闲动画、聊天未中断和隐藏暂停断言均通过。下列为三轮中位数：

| 指标 | 基线 | 重构后 |
| --- | ---: | ---: |
| UI P95 | 3.498ms | 2.376ms |
| Raster P95 | 6.996ms | 8.236ms |
| 模型更新次数 | 775 | 228 |
| 模型计算时间占采样时间 | 3.309% | 1.003% |
| 绘制提交次数 | 205,802 | 64,602 |
| 采样结束RSS | 258.8MiB | 266.8MiB |

UI P95下降32.1%，模型更新减少70.6%，六轮均没有超过16.7ms的UI／Raster帧，隐藏更新均为0。Raster P95有上升、RSS也没有下降，不能将其宣传为绘制更快或内存更少；三轮不证明长时间内存稳定。模型计算占比和提交数不等于GPU占用百分比。这里只证明对应Mac场景。[逐轮对比](qa/room-refactor-v0.6.21/native-comparison.json)、[完整设备与测试说明](qa/room-refactor-v0.6.21/device-benchmark.md)。早期失败／负载不完整的采样单独保存，未混入有效数据。

## 设备复测

使用真机profile而非debug模式。在完成SDK／授权素材准备后，连接Android手机，保持应用前台及设备不锁屏，运行：

```sh
flutter drive --profile -d <Android设备ID> --driver test_driver/performance_driver.dart --target integration_test/room_performance_test.dart --dart-define=BENCHMARK_CHAT_SCROLL=true
```

桌面用 `-d macos`、`-d windows` 或 `-d linux`。输入法压力场景附加 `--dart-define=BENCHMARK_IME=true`。脚本先验证可见模型确实更新，再进行2,000条记录／图片／流式回复和持续拖动的三次采样；记录交互避让时间、UI/Raster P95、模型CPU及隐藏后更新次数。未取得前台焦点或采样中切到后台会拒绝该组结果。

没有连接用户红米K90或RX9070／RTX4060，因此不把单元测试、CI模拟器或其他电脑的数据当作这些设备的帧率验收。单个极长且含页内锚点的Markdown、巨大表格／代码仍需设备场景复测。

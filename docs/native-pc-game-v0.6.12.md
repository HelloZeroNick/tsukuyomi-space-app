# PC 全屏、Room 动作与移动端游戏修复 · 0.6.12+18

本次问题按用户补充分开验证：Room 动作抖动发生在 PC；辉夜快跑背景音乐消失及乘坐彩叶卡死发生在移动端。

## 修改

- Windows、macOS、Linux 共用导航栏增加窗口全屏按钮，窄窗口通过菜单进入。F11 切换，Esc 退出；macOS 同时支持 Ctrl+Cmd+F。窗口状态随路由保留，并同步系统全屏操作。移动端不初始化窗口插件。
- Room 静态背景与角色分别缓存绘制，角色动作限制在固定裁剪区域内，背景、导航和控件不参与动作变换。真实 Cubism 回归逐项触发八种动作，比较背景像素与布局位置。
- 游戏工程中的上、下按键条件引用了自身，乘坐广播执行时递归无法结束；下键条件还绑在错误循环上。修复引用与绑定，并移除飞行状态中与按键无关的持续向上位移，统一上下边界。加载时预检条件图，拒绝循环引用和过深嵌套，防止无效工程进入 UI 线程执行。
- Android 游戏的多声音播放器不再逐个争夺音频焦点，背景音乐与音效可以混音；iOS 使用支持混音的 playback 会话。暂停、恢复和音量仍由游戏控制。首次播放失败展示可见提示。
- Android 发布前的原生探针实际播放游戏音乐与音效，检查 BGM 未被中断，再验证暂停与恢复；此探针使用零音量，验证播放状态，不替代真机听音。

## 验证

本地静态分析及格式检查通过，发布工具 38 项、Agent 打包工具 3 项通过。窗口、游戏和更新/导航专项回归通过，真实 Cubism 的八种动作背景像素回归通过。macOS Release 实际打开后验证全屏按钮、F11、Esc、Ctrl+Cmd+F，以及全屏中 Room → 中枢的页面切换；测试结束恢复普通窗口并退出应用。Release 内两种架构的 Agent 运行时清单及深层签名校验通过。

完整回归与五平台发布结果在完成后补充。自动化测试不能替代用户报告设备上的显示驱动、系统音频和安装交互验收；Windows / Linux 真实窗口和 Android / iOS 真机听音尚未验证，iOS 发布包仍需自行签名。

更新器从 0.6.11 起提供。旧版用户可在应用更新页面检查预览版，下载经 SHA-256 校验的 GitHub 安装包，再按系统提示安装。

# Room 聊天滚动优化

0.6.17+23 / v0.6.17-beta.1。用户反馈设备为红米K90、骁龙8至尊版；当前没有连接该Android设备。

## 修复

- `splitRoomReply`原来在每个字符处生成前文子串并匹配最后一个词，长连续文本会反复扫描。现在记录词边界，只在句末判断或可读分割处处理对应词，复用正则，保留原站URL、小数、引号、括号、代码与分句规则。
- 页面缓存已完成回复的Markdown判定和分段；流式中间状态不写入缓存。聊天图片复用同一字节实例，使Flutter的`MemoryImage`缓存保持有效，重新进入列表不重复Base64转换。
- 缓存有界：128条回复／262,144个源与分段字符，24张图片／8MiB编码字节。没有预先解析全部历史；离开Room、切换账号或站点时清空。它不是全站缓存，也不保留Widget、上下文或Cookie。
- 聊天Markdown使用`trackReading: false`，避免文章目录、进度和标题位置在聊天滚动中反复测量；文章阅读页保持原功能。聊天文字选择、格式、链接、朗读、编辑、重生成和分享继续可用。
- 聊天列表独立重绘，仍按消息ID惰性构建，预加载距离为手机360／桌面480逻辑像素。流式跟随和新轮次滚动检查用户正在拖动或惯性滚动，以及帧间位置变化；工作区等无关状态更新不再跳到列表底部。

保持2048纹理、鼠标追踪关闭、无静态立绘开屏、原生Live2D和更新弹窗。

## 兼容与回归

本地完整回归860项通过、34项可选检查跳过（真实Cubism开启）；56项聊天、布局、分句和新缓存／滚动检查通过，静态分析与242文件格式检查通过，38项发布工具检查通过。新增检查覆盖390／1280宽度的聊天Markdown无文章进度订阅、图片滚出再进入后的Provider复用及账号／站点范围切换清理、流式期间保持拖动位置、有界缓存和长连续文本。原2,000条历史按需加载／新增消息保持旧视口检查继续通过。

另用固定种子生成4,000组URL、空白、引号、括号、中文标点和代码混合文本，与修复前分句结果逐项对比，没有差异。12,000字连续文本各十次本机Dart VM热身后检查，耗时中位数993.4 → 1.64ms；这是分段CPU用例，不是手机FPS。[原始结果](qa/chat-scroll-v0.6.17/chat-reply-parser.json)。

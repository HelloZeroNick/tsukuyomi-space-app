# 辉夜快跑骑乘与异常重开 · 0.6.14+20

用户反馈来自 [文章 286](https://yachiyo.hk/articles/286)，已确认是 Android 应用，无法确定安装版本。录屏显示彩 P 骑乘后画面停止，重开出现紫黑箭头方块；原作者补充网页版正常。

## 定位与修复

当前 0.6.13 源码在完整骑乘与下车中未复现同样的自然卡死。0.6.12 已修复飞行条件自引用，但不能据此判定用户安装的版本或排除设备相关故障。本次实际复现了两项恢复缺陷：

1. 工具栏重开只清除效果和线程，旧角色仍可能可见；重置广播下一帧才恢复碰撞图的 ghost=100。若此前时钟已停止，这些紫黑箭头会持续露出。
2. 解释器异常会抛到 Ticker 回调；Flutter 在回调正常返回后才调度下一帧。异常可使时钟仍 active 却再无回调，暂停或只重开 VM 无法恢复。以受控脚本回调异常复现此链路，不把注入异常当作用户真机的已知触发原因。

重开现在恢复所有原始角色的局部变量、列表、位置、造型、大小、可见性、图层、效果、拉伸与文字，清除克隆、按键、待执行线程和累计时间，重置物理重力与边界。按原项目 reset 广播及两次零时长等待完成三次初始化调度后才通知绘制；初始化不推进游戏时间。开始画面也使用同一入口。

运行错误保留诊断信息，停止这一局并清空待执行线程、释放输入、停止声音；界面显示可重开的提示。工具栏重开会停止再启动 Ticker、重置其时间基线。运行时表达式增加 128 层上限，避免运行中变化的条件再次递归溢出；原有载入预检保留。后台暂停、分数提交、账号最高分和保存的数据不变。

## 回归证据

[修复前回归](qa/game-riding-v0.6.14/before-regressions.log)使用 `b009663` 的解释器与物理源码，在独立临时工程中运行：重开后透明效果为空、脚本错误向外抛出，两项断言均失败。未改动主工作区以复现旧行为。

[游戏专项回归](qa/game-riding-v0.6.14/game-regressions.log)包括原有 15 项与新增 6 项：真实 PNG 掩码碰撞触发骑乘，完整上下移动、暂停、亮度闪烁、下车恢复操作、骑乘中重开、骑乘死亡后重开，连续三轮；局部状态、物理和半帧累计量重置；运行中条件循环；真实 Ticker 故障隔离；页面实际提示与点击重开恢复。19 个绘制阶段中，9 次重开首帧与第一次全新开场的 480×360 RGBA 像素逐字节一致。

离线探针只调整关卡进度到飞船生成阈值并保持生存，真实碰撞与原项目骑乘脚本照常执行。它不创建 GameSession，也不向服务器提交测试分数。Android Release 的原生探针复用这些场景和像素断言，必须输出 `TSUKUYOMI_GAME_RIDING_OK` 才允许发布。

本地完整回归 809 项通过、33 项可选环境检查跳过，静态分析和格式检查通过；发布工具 38 项、Agent 打包工具 3 项通过。macOS Release 的真实 Metal / Impeller GPU 探针完成同样 19 个绘制阶段和 9 次首帧像素比较，全部通过，原有 Live2D 绘制和细节探针也通过。见 [本地验证摘要](qa/game-riding-v0.6.14/local-validation.json)。五平台 CI、Android 原生探针及发布文件完整性结果在发布后补充。当前没有用户那台 Android 物理设备，不能将宿主测试或模拟器通过当作用户真机已经验收。网站工作区和游戏素材文件未修改。
